## 0. なぜやるか

現状カレンダーは「予定を確認する道具」で完結している。v11 の目的は "**開いてない時も存在感、開いたら温もり**" — アプリを日常の背景に溶け込ませ、二人の距離を近く感じさせる。

v11.0 では以下を実現:
- タブ/アイコンが二人の状況(今日休みか、来週デートか)を静かに主張
- 時間帯や季節と共に画面が息づく
- ワンタップで相手に「思い出したよ」を届けられる
- 各日付にメッセージスレッドで温度を残せる

## 1. アーキテクチャ

| レイヤ | 内容 |
|---|---|
| 識別子管理 | 自分が「こうき」か「ゆい」かを設定シートで選択、localStorage 保存 |
| 信号層 | 新 Firestore collection `signals/pulse` (1ドキュメント上書き)、onSnapshot で両端末即受信 |
| メッセージ層 | 新 Firestore collection `notes/{YYYY-MM-DD}` (per-日ドキュメント、messages array)、既存 dateMemo から自動移行 |
| ビジュアル層 | favicon/title/背景 の3系統を `updateAmbient()` 共通関数で 15分毎+日跨ぎで更新 |

**個人情報の扱い**: 交換日記の text は個人メッセージ。既存 events メモと同じく Firestore 経由(Google Cloud 管理下)。過去合意通り現状受容(GitHub Pages 公開状態 → [feedback_shift_cal_privacy] 参照)。

## 2. コンポーネント分解

| ユニット | 責務 | データ | 依存 |
|---|---|---|---|
| `identityStore` | 自分の person key を localStorage で保持 | localStorage `sc_my_person` | なし |
| `updateFavicon()` | 状態(通常/両休み/給料日/記念日)判定→SVG data URI で favicon 差替 | 既存 EVENTS/HOLIDAYS/anniversaries | render() 済のデータ |
| `updateTabTitle()` | 優先順位付きで document.title 動的更新 | 同上 | 同上 |
| `applyTimeTheme()` | 現在時刻から朝/昼/夕/夜のグラデ選択、body/カレンダー領域に適用 | Date.now() | なし |
| `updateAmbient()` | 上3つを一括呼び出し。init時+15分間隔+visibilitychange | 同上 | 同上 |
| `Storage.sendPulse()` | signals/pulse 上書き | Firestore | firestore SDK |
| `Storage.onPulseSnapshot(cb)` | signals/pulse 購読 | Firestore | firestore SDK |
| `spawnHearts(count)` | 画面下部から💗をふわっと8個上へ | DOM | なし |
| `Storage.appendNote(key, text)` | notes/{key}.messages を arrayUnion | Firestore | firestore SDK |
| `Storage.markNoteRead(key, msgId)` | notes/{key}.messages[].readBy に自分追加 | Firestore | firestore SDK |
| `Storage.onNotesSnapshot(cb)` | 現在月+隣接月の notes 購読 | Firestore | firestore SDK |
| `renderNoteThread(key)` | day-overlay 内に thread UI 描画 | メモリ内 notes cache | Storage |
| `computeUnreadBadges()` | 月グリッド用の未読数マップ計算 | notes cache | なし |

**インターフェース例:**
- `identityStore.get() → 'kouki' | 'yui' | null`
- `identityStore.set('kouki')`
- `Storage.sendPulse() → Promise<void>` (最後の setDoc)
- `Storage.onPulseSnapshot(cb: (data) => void) → unsubscribe fn`

## 3. Dynamic favicon 詳細

**4 state + 優先順位:**

| 順位 | 状態 | 判定条件 | favicon(SVG viewBox 32x32) |
|---|---|---|---|
| 1 | 記念日 | 今日 anniv 一致(type 別) | 🎂/💗/🌸 の SVG(既存 st-cake/heart/st-star reuse) |
| 2 | 給料日 | 今日 salary_events 一致 | 💰 コイン風 (leaf gradient) |
| 3 | 両休み | 今日 isBothOff(EVENTS) | 💗 ハート(cheek gradient) |
| 4 | 通常 | 上記いずれでもない | 🐸 ケロッピー(既存 frog を 32px 化) |

**書き換え頻度:**
- init 時に 1 回
- `setInterval(15分)` で日跨ぎ検出 → 前回計算日 !== 今日なら再判定
- `visibilitychange` で visible 復帰時に即再判定

**SVG インライン化:** 各 state 用 SVG を code-side に `const FAV_TEMPLATES = { normal: '<svg>...</svg>', ... }` として保持。`updateFavicon()` は `link.href = 'data:image/svg+xml;utf8,' + encodeURIComponent(svg)` で差替。

**互換性:** iOS Safari は動的更新を無視する場合あり(退化はしない、初期表示は出る)。Chrome/Firefox/Edge/Android Chrome で動作を目標。

## 4. タブ countdown 詳細

**優先順位:**

1. **今日が特別な日** → 「💗 今日はふたりお休み」「💰 今日は給料日」「🎂 今日は名前の誕生日」
2. **7日以内に何かある** → 「あと3日でデート」等、最近接1件
   - 対象: 記念日 / 誕生日 / 給料日 / 両休み予定日
3. **何もない期間** → 「カレンダー(2026年8月)」通常タイトル

**フォーマット:**
- X = 0 → 「今日は」に置換、X = 1 → 「明日は」
- 末尾に ` ・カレンダー` を必ず付与(ブランド)

**更新頻度:** favicon と同じく `updateAmbient()` で共通。`document.visibilityState === 'hidden'` の間はスキップ。

## 5. 時間帯背景 詳細

**4 パターン:**

| 時間帯 | 時刻 | body background |
|---|---|---|
| 朝 | 5:00-9:59 | `linear-gradient(180deg, #FFE4B5 0%, #FFF8F0 100%)` |
| 昼 | 10:00-15:59 | `linear-gradient(180deg, #E0F2FE 0%, #FFF8F0 100%)` |
| 夕 | 16:00-18:59 | `linear-gradient(180deg, #FDBA74 0%, #FFE4E1 100%)` |
| 夜 | 19:00-4:59 | `linear-gradient(180deg, #1E3A8A 0%, #4B3F72 100%)` |

**適用対象:**
- `body` の背景を上書き(既存 `--bg` を JS で `body.style.background = ...` で上書き)
- header は既存の**シーズンアクセント(月別)**が優先 → 時間帯背景は body/カレンダー領域のみ
- カレンダーセルは既存 `--surface`(白系)継続 → 夜モードでも可読性維持

**遷移:**
- 15分毎 setInterval → パターン変わったら CSS `transition: background 0.8s ease` で滑らか切替
- 開いた瞬間は transition なし(即適用)

**アクセシビリティ:**
- `@media (prefers-reduced-motion: reduce)` で transition 削除
- 夜モードでもテキスト濃色維持 → コントラスト十分

## 6. 💗ボタン(pulse)詳細

**UI:**
- ヒーローカード右上に丸ボタン(直径 36px)、ハート SVG(既存 #heart)
- ホバー/タップで軽い pulse アニメ
- 5秒 disabled(連打防止、disabled 中はカウントダウン数字)

**フロー:**
1. タップ → 自分の画面に💗8個ふわり(1.5秒)
2. `Storage.sendPulse()` = Firestore `signals/pulse` に `{from: myKey, ts: serverTs, kind: 'heart'}` を setDoc
3. 相手の onSnapshot 発火 → `data.from !== myKey && data.ts > lastSeenPulseTs` 判定
4. 相手画面に💗8個ふわり + `navigator.vibrate([80, 40, 80])`

**自分identity 判定:**
- 設定シートに新規セレクタ追加(こうき/ゆい 択一)
- localStorage `sc_my_person` に保存
- 未設定時は💗ボタンを disabled + 「まず設定で自分を選んでください」ツールチップ

**Firestore スキーマ:**
```
signals/pulse
  from: "kouki" | "yui"
  ts: Timestamp
  kind: "heart"
```
1ドキュメント固定、常に上書き。書き込みコスト最小(月 ~1000 回想定、無料枠内)。

**受信時 hidden タブ挙動:**
- タブ hidden 中に受信 → visible 復帰時に latest signal 確認 → new なら遅延演出発火
- WebPush は v11.0 では非対応

**アニメ:**
既存の heart-float CSS 拡張。8個を横 stagger でランダム位置から発生:
```css
@keyframes heart-fly-up {
  from { opacity: 0; transform: translateY(0) scale(0.6); }
  30%  { opacity: 1; }
  to   { opacity: 0; transform: translateY(-320px) scale(1.2) rotate(15deg); }
}
```

## 7. 交換日記(notes)詳細

**Firestore スキーマ:**
```
notes/{YYYY-MM-DD}
  messages: [
    {
      id: string           // uuidv4-like
      from: "kouki" | "yui"
      text: string         // 制限 200文字
      ts: Timestamp        // client 時刻(Firestore serverTimestamp は array 内で使えない)
      readBy: ["kouki"|"yui"]  // 自分の from が入ってれば既読
    }
  ]
  updatedAt: Timestamp  // serverTimestamp
```

**UI(day-overlay 内):**
- 既存 dateMemo セクションを **交換日記スレッド** に置換
- スレッド表示:
  - 相手側: 左寄せカード `[こうき 20:15] 今日お疲れさま`
  - 自分側: 右寄せカード `お疲れ [ゆい 20:16] ✓既読`
  - 未読は少し目立たせる背景色
- 入力エリア: 下部に固定 `<input type="text">` + 送信ボタン
- スクロール: 最下部が最新、初回開時に自動最下部スクロール

**既存 dateMemo との移行:**
- 初回 fetch 時に notes/{key} が空 & 既存 memo あり → 自動で messages[0] として変換 → 保存
- 以降は notes/{key} のみ使用
- 既存 memo データは削除しない(後方互換)

**未読バッジ:**
- カレンダーグリッドの日付セル右上に **未読バッジ**(赤丸 8x8px + 小数字)
- 判定: message.from !== myKey && !message.readBy.includes(myKey)
- カウント: バッジ内に数字表示、9件以上は「9+」
- 開いた瞬間に visible messages を `markNoteRead` で既読化 → 全端末で反映

**onSnapshot 最適化:**
- 全 notes を listen するとコスト大 → **現在月+前後1ヶ月** のみ listen
- 月切替のたびに listener 再構築
- 実装: `query(notes, where('__name__', '>=', firstDay), where('__name__', '<=', lastDay))`

**書き込みコスト:**
- appendNote: 日 5-20 回想定 → 月 400 回
- markNoteRead: 日 10-30 回 → 月 700 回
- 無料枠 20k writes/day に対して余裕

## 8. Firestore rules 追記

`firestore.rules` に以下を追加:
```
match /signals/{docId} {
  allow read, write: if request.auth != null;
}
match /notes/{docId} {
  allow read, write: if request.auth != null;
}
```

**デプロイ:**
- `firebase deploy --only firestore:rules --project karenda-eba3e` を私が実行

## 12. ロールバック条件

- Firestore rules デプロイミス → console から即巻き戻し
- 15分間隔 timer による battery drain → 30分に緩和 or 削除
- 交換日記の書き込み頻度が予測超過 → per-月 sharding、または未読の onSnapshot 頻度削減
- 既存機能(day-overlay の memo、履歴シート、記念日カウントダウン、サマリーカード)の regression → 該当コミット revert
- HTMLサイズ 30% 超変動 → コミット分割見直し

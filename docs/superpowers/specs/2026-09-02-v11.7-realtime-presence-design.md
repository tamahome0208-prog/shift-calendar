## 1. アーキテクチャ

| レイヤ | 内容 |
|---|---|
| 状態層 | 新 Firestore collection `presence/{personKey}`、1ドキュメント/人 |
| 書き込み層 | `presenceStore` で内部 buffer + throttle 2000ms → `Storage.writePresence()` |
| 購読層 | `Storage.onPresenceSnapshot(cb)` で両者分保持、非自分の分を UI 反映 |
| 描画層 | `PartnerCursor` DOM 要素、smooth `transition: transform 0.5s ease` で書込間隔のカクつき緩和 |
| 検出層 | `OverlapDetector` が両者 `presence.cell` を比較、2秒キープで演出発火 |
| 演出層 | `spawnOverlapCelebration(cell)` = 💗8個+バイブ+セル温度色グラデ |
| 設定 | 「相手カーソルを表示する」トグル(localStorage、デフォルト ON) |

**個人情報の扱い:**
- 位置 = カレンダー画面内の相対 px 座標(実世界 GPS ではない)
- カレンダー画面から離脱(overlay 開くなど) or visibility hidden で即 `active: false`
- 両者 identity 未設定 or 設定トグル OFF なら機能停止

**Firestore コスト:**
- move 中 throttle 2000ms → 1秒あたり 0.5 write
- 4h/day × 2端末 × 実移動時間の 25% ≒ 3600 writes/day
- Spark 無料枠 20k/day に対し 18%、余裕あり

## 2. コンポーネント分解

| ユニット | 責務 | 入力 / 状態 | 依存 |
|---|---|---|---|
| `presenceStore` | 位置/セル/active を throttle して write | 内部 buffer(x, y, cell) + 最終送信時刻 | Storage |
| `Storage.writePresence(data)` | Firestore `presence/{me}` に setDoc | data = {x, y, cell, active, lastPing} | firestore SDK |
| `Storage.onPresenceSnapshot(cb)` | `presence` collection 全件 listen、相手データ抽出して cb | 相手 identity 判定 | firestore SDK |
| `PartnerCursor` | 相手カーソル DOM 描画 + smooth transform | 相手 presence data | DOM |
| `OverlapDetector` | 両者 cell 一致検出、2秒 hold で演出発火 | 自分の hoverCell + 相手 presence.cell | なし |
| `spawnOverlapCelebration(cellKey)` | 💗爆発 + バイブ + セル温度演出 | cell DOM 要素 | 既存 spawnHearts / navigator.vibrate |

**インターフェース:**
- `presenceStore.updatePosition(x, y, cellKey)` — 内部で throttle、直近値保持
- `presenceStore.setActive(bool)` — visibility 変化 / overlay 開閉時に呼ぶ
- `PartnerCursor.render(partnerData)` — 位置更新、null なら非表示
- `OverlapDetector.check(myCell, partnerCell)` — pointermove 毎に呼ぶ、時間ロジック内蔵

**既存への影響:**
- `pointermove` / `pointerdown` の listener 追加(カレンダー領域のみ)
- overlay 開閉時に `presenceStore.setActive(false/true)` 呼び出し
- 設定シートに新規トグル追加
- Firestore rules に `/presence/{personKey}` 追加

## 3. presence Firestore スキーマ

```
presence/{personKey}  // personKey = "kouki" | "yui"
  x: number         // 0-1 相対座標(画面幅で正規化)
  y: number         // 0-1 相対座標(画面高で正規化)
  cell: string|null // 現在ホバー中のセル key "YYYY-MM-DD"
  active: bool      // false ならカーソル非表示
  lastPing: Timestamp
```

**なぜ x/y を 0-1 相対にするか:**
- 画面サイズが違う端末間でも位置を再現できる
- 幅 375px スマホ vs 幅 800px iPad でも同じ相対位置

**書き込みトリガー:**
1. `pointermove`(内部 buffer 更新のみ)→ 2000ms throttle → write
2. `pointerdown` → 即 write(タッチ検出は遅延なしにしたい)
3. 静止 5秒 → `active: false` に更新
4. `visibilitychange` hidden → `active: false`
5. `beforeunload` → `active: false`
6. 主要 overlay(day/settings/history/report/year/shift-upload) open → `active: false`
7. 主要 overlay close → `active: true`

**購読側の反応:**
- `onPresenceSnapshot` で全 presence を受信
- 自分の identity と一致しない doc = 相手 → 描画対象
- `active: false` なら PartnerCursor 非表示
- lastPing から 30秒以上経過も非表示(古い state 保険)

## 4. 相手カーソル UI

**HTML:**
```html
<div id="partner-cursor" style="display:none;">
  <svg class="cursor-icon"><path d="..."/></svg>
  <span class="cursor-label" id="partner-name"></span>
</div>
```

**CSS:**
```css
#partner-cursor {
  position: fixed;
  pointer-events: none;
  z-index: 9997;
  transition: transform 0.5s cubic-bezier(0.25, 0.46, 0.45, 0.94), opacity 0.3s ease;
  will-change: transform;
}
.cursor-icon {
  width: 20px;
  height: 20px;
  fill: var(--partner-color);
  filter: drop-shadow(0 1px 2px rgba(0,0,0,0.2));
}
.cursor-label {
  display: inline-block;
  margin-left: 4px;
  padding: 2px 6px;
  background: var(--partner-color);
  color: white;
  border-radius: 8px;
  font-size: 11px;
  font-weight: 800;
  white-space: nowrap;
}
```

`--partner-color` は識別子で変更:
- 自分 = こうき → 相手カーソル = pink(`--yui`)+ 名前「ゆい」
- 自分 = ゆい → 相手カーソル = blue(`--kouki`)+ 名前「こうき」

**アニメ:**
- 位置更新は `transform: translate(x, y)` で反映
- 表示/非表示は opacity + `display` 切替
- 500ms transition で 2000ms 間隔でも滑らかに見える

**セル hover アウトライン:**
- 相手が hover 中のセルには薄い outline(`box-shadow: inset 0 0 0 2px var(--partner-color)`)
- 自分の hover とは別色で区別

## 5. 重ねタッチ演出

**判定ロジック:**
1. `pointerdown/pointermove` で自分の hoverCell を追跡
2. 相手 presence.cell と自分の hoverCell を比較
3. 一致した瞬間から 2秒タイマー起動
4. 途中で外れたらタイマーリセット
5. 2秒経過 & 両者まだ一致 → `spawnOverlapCelebration(cell)`
6. 発火後は 10秒 cooldown(連発防止)

**演出:**
- 該当セルの背景色が青→紫→ピンク→オレンジと 1秒でグラデ遷移
- `spawnHearts(12)` で💗爆発(既存関数を数増しで再利用)
- `navigator.vibrate([100, 50, 100, 50, 200])`
- セルに `class="overlap-celebrated"` 追加、1秒後 remove
- toast 「💗 重ねタッチ!」を上部に 2秒表示

**CSS:**
```css
.day-cell.overlap-celebrated {
  animation: overlap-glow 1s ease;
}
@keyframes overlap-glow {
  0%   { background: rgba(87, 176, 220, 0.4); }
  33%  { background: rgba(183, 100, 220, 0.4); }
  66%  { background: rgba(247, 100, 162, 0.4); }
  100% { background: rgba(255, 200, 100, 0.4); }
}
```

## 9. 範囲外(YAGNI)

- 3人以上の presence(couple 用途、YAGNI)
- 音声出力(タブ非表示時に鳴ると迷惑)
- カーソル移動履歴の可視化(オーバー)
- 過去 presence の永続化
- 自分の姿を相手が見てる時のみ表示(逆遠隔感、複雑)
- WebRTC / RTDB(実装重い、Firestore で十分)

## 10. アクセシビリティ

- 相手カーソルは decorative なので `aria-hidden="true"`
- 重ねタッチ演出は `prefers-reduced-motion` で無効化
- 設定シートで機能 OFF 可能

---

## 11. パフォーマンス

- Firestore write: 2s throttle + 静止時停止 → 平均 <1 write/s
- pointermove 内部 buffer 更新は軽量(数バイトの代入のみ)
- PartnerCursor は 1 DOM 要素で `transform` のみ更新、reflow なし
- OverlapDetector は render サイクル毎の O(1) 比較

## 12. テスト計画

| 観点 | 検証 |
|---|---|
| 自分の presence write | pointermove → 2秒後に Firestore console で確認 |
| 相手カーソル表示 | 別端末で開いて自分側にカーソル現れる |
| 静止 5秒 | active:false 反映で相手側からカーソル消える |
| overlay open | day/settings 開いた瞬間に active:false |
| visibility hidden | タブ切替で active:false |
| 重ねタッチ | 両端末で同じ日をタッチ → 2秒後に演出発火 |
| cooldown | 演出直後 10秒は再発火しない |
| reduce-motion | 演出無効 |
| 設定 OFF | 自分の write 停止 + 相手カーソル非表示 |
| identity 未設定 | 機能完全 OFF |

---

## 13. ロールバック条件

- Firestore write 頻度が予測超過 → throttle 5000ms に緩和 or 機能 revert
- 相手カーソルがカクつき視覚的にストレス → smooth transition 時間延長 or 表示単位を 5秒に変更
- rules デプロイミス → firebase console で巻き戻し
- 既存機能(pointerdown ハンドラ等)への regression → 該当 commit revert
- 電池消費体感増 → 静止判定を短く、visibility check 強化

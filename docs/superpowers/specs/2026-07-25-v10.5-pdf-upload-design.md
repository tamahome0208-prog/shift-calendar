# シフトカレンダー v10.5「サイト内 PDF アップロード」設計

**日付**: 2026-07-25
**ターゲット**: https://tamahome0208-prog.github.io/shift-calendar/
**スコープ**: ユーザーが毎月のシフトPDFをブラウザから直接アップロード、パース、プレビュー編集して Firestore に保存できるようにする
**目的**: Claude に毎月依頼せず、ゆい/こうきどちらの端末からでもPDF投入で更新完了する状態にする
**コミット計画**: 4-5コミット、合計 550-700行

---

## 0. なぜやるか

現状、6月・7月・8月のシフトデータは私(Claude)が pdfplumber で抽出して build.py に hardcode してコミットしている。
毎月これを繰り返すのは面倒で、ユーザー主導で完結する仕組みが欲しい。

**要件:**
- ユーザーがサイト内でPDFを選ぶだけで完結
- パース結果をプレビューで確認・修正可能
- 両端末(こうき+ゆい)で即同期(Firestore 経由)
- 個人情報を外部サービスに送信しない(完全ローカル解析)

## 1. アーキテクチャ

| レイヤ | 内容 |
|---|---|
| ライブラリ | **pdfjs-dist**(CDN 経由 lazy load、初回アップ時のみロード)。SheetJS 等は使わない |
| 抽出ロジック | pdfjs で 1ページ目のテキストアイテムを座標付き取得 → 行/列にグルーピング → 「安中」「恩田」列を切り出し、日別 label を得る |
| データ格納 | 新 Firestore collection **`shifts`**、docId=`YYYY-MM`(例 `2026-08`)、`{ym, events:[{d, person, summary}], updatedAt}` の1ドキュメント/月 |
| 描画マージ | build-time 定数 `EVENTS` + ランタイム `firestoreShifts[ym]` の順で **月まるごと差し替え** |
| プレビュー UI | overlay シート内で月グリッド表示、各セルタップでインライン編集、下の「保存」で Firestore 書き込み |

**個人情報の扱い:**
- PDF は完全にローカル解析、外部送信ゼロ
- 元 PDF は保存しない、抽出後の events 配列のみ Firestore へ
- 表示名は既存 `NAME_MAP` で 安中→こうき / 恩田→ゆい へマップしてから保存

## 2. コンポーネント分解

| ユニット | 責務 | 依存 |
|---|---|---|
| `ShiftPDFParser.parse(file)` | pdfjs-dist で PDF→`{ym, events[]}` を抽出。失敗時 throw | pdfjs-dist |
| `ShiftUploadSheet` (JS+HTML) | ファイル選択 → パース起動 → プレビュー → 編集 → 保存 の UI 状態機械 | ShiftPDFParser, Storage |
| `Storage.saveShifts(ym, events)` | Firestore `shifts/{ym}` に `setDoc`、全上書き | firestore SDK |
| `Storage.onShiftsSnapshot(cb)` | `shifts` collection の onSnapshot 購読、`firestoreShifts` を更新して render() 再走 | firestore SDK |
| `mergeEventsWithShifts(EVENTS, firestoreShifts)` | 描画用に per-月マージした events dict を返す純関数 | なし |

**インターフェース:**
- `ShiftPDFParser.parse(file: File) → Promise<{ym: string, events: {d: number, person: 'こうき'|'ゆい', summary: string}[]}>`
- 失敗時: `throw new Error(理由文字列)` (プレビューの赤バナーに表示)

**既存への影響:**
- `EVENTS` 定数は変えない(フォールバック用)
- `render()` は `EVENTS` の代わりに `mergedEvents` を参照(1行修正)
- Firestore rules に `shifts` collection の許可ルール追加

## 3. PDF パースロジック

### 入力仮定
1ページ目に「日別×スタッフ列」のテーブル、列ヘッダに「安中」「恩田」を含む。ver3 8月PDF と同構造を前提。

### 手順
1. `pdf.getPage(1).getTextContent()` で全 text item を座標付き取得
2. Y座標クラスタリングで行にグルーピング(±3px、行数少ない場合は ±5px にフォールバック)
3. 「安中」「恩田」文字列の X 座標を検出 → 列位置確定
4. 日付行(1-31 の数字が先頭)を各行スキャン → 該当列 X 付近のテキスト item を取得
5. `{day, kouki_label, yui_label}` 配列生成
6. `{d, person: 'こうき'|'ゆい', summary}` にフラット化。空文字は entry なし
7. タイトル行から `年` `月` を抽出 → `ym = "YYYY-MM"`

### 失敗ケース

| 種類 | 対応 |
|---|---|
| 「安中」or「恩田」列が見つからない | プレビューを空データで開き、年月と各日 summary をユーザー手入力可能に |
| ページ0件 or テーブル未検出 | エラー: "テーブルを検出できません" + 再選択ボタン |
| タイトルから年月抽出失敗 | プレビュー上部の 年/月 セレクタで手動指定(デフォルト現在月+1) |
| A番/MTG/出張 等の値 | そのまま summary 文字列として保存(バリデーションは緩め) |

## 5. エラー処理・セキュリティ

### Firestore ルール
`firestore.rules` に追記:
```
match /shifts/{ym} {
  allow read, write: if request.auth != null;
}
```
既存の events/anniversaries と同じパターン、匿名認証済みユーザーのみ read/write。ルールは手動デプロイ(既存フロー踏襲、build.py から自動化はしない)。

### 主要エラー処理

| ケース | 挙動 |
|---|---|
| PDF が壊れている / パースエラー | catch し、赤バナー「PDFを読み込めませんでした」+ 再選択ボタン |
| 「安中」「恩田」列が見つからない | 空のプレビューを開き、ユーザー手入力可能に |
| 年月抽出失敗 | プレビューの年/月 セレクタで手動指定 |
| Firestore 書き込み失敗(オフライン等) | toast「保存失敗。オフラインです」+ localStorage に一時保存 → 復帰時に自動再送(C5 コミットで実装) |
| 30MB超のPDF | 事前チェックしてエラー「ファイルサイズが大きすぎます」 |

### セキュリティ

- PDF は **完全にローカル解析**、外部送信ゼロ
- pdfjs-dist は unpkg CDN からロード(ライブラリ自体は本人の PDF に触れない)
- Firestore へは events 配列(数値・短文字列のみ)を書き込み、元 PDF ファイルは保存しない
- 個人名(安中/恩田)は `NAME_MAP` 経由で こうき/ゆい にマップされてから保存
- Firestore rules で auth 済みユーザーのみ操作可

## 6. データモデル

### Firestore `shifts` collection
```
shifts/{ym}
  ym: string        // "2026-08"
  events: [
    { d: number, person: "こうき"|"ゆい", summary: string }
  ]
  updatedAt: Timestamp
```

**なぜドキュメント1件/月:**
- 月単位で全上書きが自然
- 読み込み効率(月切替時、必要な月のみ取得可)
- listener を collection 全体に張っておけば onSnapshot で自動同期

### 描画マージロジック
```javascript
function mergeEventsWithShifts(builtinEvents, firestoreShifts) {
  const merged = { ...builtinEvents };
  for (const [ym, doc] of Object.entries(firestoreShifts)) {
    // その月の EVENTS キーを全削除
    Object.keys(merged).forEach(k => {
      if (k.startsWith(ym + '-')) delete merged[k];
    });
    // Firestore データで置き換え
    doc.events.forEach(({d, person, summary}) => {
      const key = `${ym}-${String(d).padStart(2, '0')}`;
      merged[key] = merged[key] || [];
      merged[key].push({person, summary});
    });
  }
  return merged;
}
```

## 9. 範囲外(YAGNI)

- 過去アップロード履歴の表示(いつ何をアップしたか)
- 同月アップ時の diff 表示(前回との差分ハイライト)
- xlsx サポート(PDF 一本に絞ることを合意済み)
- 個人ごとの列指定 UI(スタッフが増える場合の対応、現状は「安中」「恩田」固定検出)
- 出店場所・会議時刻の詳細抽出(summary 文字列のみ抽出、詳細は既存 custom event で手動追加)
- 削除 UI(誤って全上書きしても、正しい PDF を再アップすれば直る)

## 10. ロールバック条件

- pdfjs-dist ロード失敗が頻発 → CDN から static 同梱に切替、または v10.4 に戻す
- Firestore rules デプロイミスで read/write が全ブロック → 手動で rules を巻き戻し
- パース精度が実運用で 50% 未満 → プレビュー編集で埋められるが、パースロジック見直し必須
- HTMLサイズ 30% 超 → C1 のライブラリロード方式を dynamic import に厳密化
- 既存機能(day-overlay, 履歴シート, 記念日, カウントダウン, サマリーカード)の regression → 該当コミットを revert
